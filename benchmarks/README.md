# 음악 교육 웹·앱 벤치마크

이 폴더는 개별 서비스 분석을 서로 비교하기 위한 공통 기준을 정리한다.

## 우선 분석 대상

| 서비스 | 핵심 영역 | 우선 확인할 것 |
|---|---|---|
| Chrome Music Lab Song Maker | 피아노롤형 작곡 | 터치 입력, 색상, 즉시 재생, 공유 |
| Ableton Learning Music | 음악 개념 학습 | 단계형 설명, 실험 UI, 청음 연결 |
| Groove Pizza | 리듬·수학 | 원형 시퀀서, 패턴 시각화, 접근성 |
| Flat for Education | 기보·수업 | 오선보 입력, 과제, 협업, 제출 |
| Noteflight Learn | 기보·평가 | 악보 편집, 교육 계정, 평가 |
| 기타 초등 음악 도구 | 수업 특화 | 진입 비용, 모바일, 교사 운영 |

## 서비스별 공통 분석표

### 1. Product

- 대상 사용자
- 핵심 문제
- 주요 사용 장면
- 수업에서의 위치

### 2. Learning Design

- 학습 목표
- 개념 도입 방식
- 탐색 활동
- 창작/연주 활동
- 피드백
- 성찰/발표

### 3. Information Architecture

- 첫 화면
- 페이지/탭 구조
- 주요 단계
- 뒤로 가기/복귀
- 저장된 작품 접근

### 4. Interaction

- 클릭
- 터치
- 드래그
- 키보드
- 재생
- undo/redo
- 복사/변형

### 5. Music Representation

- 오선보
- piano roll
- step sequencer
- 원형 리듬
- 코드
- 음계
- 계이름/음이름
- 색상

### 6. Music Theory Engine

- 조성
- 음계
- 리듬
- 박자
- 화음
- 비화성음
- 종지
- 전조
- 기보 규칙

### 7. Audio

- 샘플/신시사이저
- 동시 발음
- scheduling
- tempo
- metronome
- loop
- latency

### 8. Data

- song state
- 저장 방식
- 작품 수
- version/history
- 공유 포맷
- import/export

### 9. Teacher Workflow

- 학생 입장
- 과제 배포
- 제출
- 교사 모아보기
- 피드백
- 발표
- 인쇄

### 10. Accessibility

- 키보드
- screen reader
- 색상 의존성
- 터치 타깃
- 소리 없이도 이해 가능 여부
- 움직임/애니메이션

### 11. Implementation Evidence

각 항목에 반드시 다음 중 하나를 붙인다.

- **Observed** — 실제 화면/DOM/공개 소스에서 확인
- **Documented** — 공식 문서에 명시
- **Inferred** — 외부 동작에서 추정
- **Unknown** — 확인 불가

## 비교 시 핵심 질문

단순히 “기능이 더 많다”가 아니라 다음을 비교한다.

1. 학생이 처음 30초 안에 무엇을 할 수 있는가?
2. 음악 이론을 UI에 어떻게 번역했는가?
3. 잘못된 입력을 막는가, 허용하고 설명하는가?
4. 소리와 시각 표현이 얼마나 직접 연결되는가?
5. 수정이 얼마나 쉬운가?
6. 결과를 실제 악보/연주/수업 결과물로 옮길 수 있는가?
7. 교사가 20~30명의 결과를 관리할 수 있는가?
8. 학생의 자유도와 학습용 제약을 어떻게 균형 잡는가?

## 최종 비교 산출물

서비스가 충분히 쌓이면 다음 표를 유지한다.

| 서비스 | 진입성 | 음악이론 | 창작 자유도 | 피드백 | 기보 | 교사 운영 | 모바일 | 재구현 가치 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Major-Minor Composer | 높음 | 중상 | 중 | 높음 | 낮음 | 중 | 높음 | 높음 |

점수는 단순 순위가 아니라 각 서비스의 목적을 이해하기 위한 보조 지표로만 사용한다.
