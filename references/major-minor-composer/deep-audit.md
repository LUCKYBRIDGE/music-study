# 심층 감사 — Major / Minor Composer

- 대상: **작곡소 — 장조·단조로 네 마디 노래 만들기**
- 분석 기준: 실제 화면 캡처 4장 + 현재 브라우저 DOM 텍스트 + 교육과정 대조
- 분석일: 2026-11-11
- 분석 방법: 관찰(Observed), 문서 확인(Documented), 추정(Inferred), 미확인(Unknown) 분리
- 목적: 단순 UI 리뷰가 아니라 **학습 설계와 실제 구현 논리를 재구성할 수 있는 수준**으로 분석

---

# 0. 핵심 결론

이 도구의 본질은 간단한 작곡기보다 **제약 기반 창작 학습 환경(constrained creative learning environment)** 에 가깝다.

학생에게 처음부터 모든 음악 요소를 주지 않고 다음 순서로 자유도를 단계적으로 연다.

~~~text
느낌 선택
→ 장조/단조 결정
→ 조 결정
→ 마디별 화음 결정
→ 한 박 단위의 음 시작점 입력
→ 반복·변형 도구 사용
→ 화음 관계 피드백
→ 네 마디 구조 확인
→ 가락 윤곽과 형식 확인
→ 실제 피아노 연주로 연결
~~~

좋은 점은 기능 수보다 **학생의 의사결정을 작은 단위로 쪼갠 것**이다. 반대로 가장 큰 한계는 교육적으로 강한 안내가 때때로 음악적으로 가능한 선택을 맞음/부딪힘처럼 너무 강하게 판정한다는 점이다.

# 1. 사용자 과업 모델

| 단계 | 화면 행동 | 학생의 인지 과업 | 시스템 역할 |
|---|---|---|---|
| 1 | 장조/단조 듣기 | 느낌 비교 | 두 조건으로 선택 공간 축소 |
| 1 | mode 선택 | 곡의 정서적 방향 결정 | 사용할 조 후보 변경 |
| 2 | 조 선택 | 중심음·조표·사용 음 비교 | scale material 제한 |
| 3 | 화음 선택 | 마디별 어울림 결정 | 안정적 pitch 후보 제공 |
| 3 | 그리드 클릭 | 가락 구성 | 시간/음높이 좌표로 기록 |
| 3 | 재생 | 결과 청음 | 즉시 auditory feedback |
| 3 | 복사/변형 | 반복과 변화 경험 | composition operation 자동화 |
| 3 | 피드백 확인 | 화음 관계 검토 | 설명형 제안 |
| 4 | contour 확인 | 전체 가락의 모양 파악 | 추상적 구조 시각화 |
| 4 | a/a′ 확인 | 반복·변형 관계 파악 | 패턴 언어로 번역 |
| 4 | 피아노 안내 | 디지털 결과를 연주로 전환 | 실제 건반 정보 제공 |
| 전체 | 곡 서랍 | 여러 작품 비교 | 버전/후보 보존 |

시스템이 실제로 묻는 질문은 작다.

1. 밝은 쪽인가, 어두운 쪽인가?
2. 어느 조를 쓸 것인가?
3. 이번 마디의 화음은 무엇인가?
4. 어느 박에 어느 음을 놓을 것인가?
5. 앞 마디를 반복할 것인가, 바꿀 것인가?
6. 어떤 버전을 발표할 것인가?

이 **decision decomposition**이 가장 재사용 가치가 높다.

# 2. 정보 구조와 상태 전이

## 2.1 최상위 상태

~~~ts
type AppState = {
  step: 1 | 2 | 3 | 4
  mode: "major" | "minor"
  keyId: string
  currentSlotId: string
  selectedBar: 0 | 1 | 2 | 3
  bars: BarState[]
  accompanimentEnabled: boolean
  slowPlayback: boolean
  history: Snapshot[]

~~~

## 2.2 화면 전이

~~~text
STEP 1
  ├─ 장조 선택 → STEP 2 / major key candidates
  └─ 단조 선택 → STEP 2 / minor key candidates

STEP 2
  └─ 조 선택 → STEP 3 / scale + harmony config

STEP 3
  ├─ 편집 계속
  ├─ 슬롯 저장
  └─ 완성곡 보기 → STEP 4

STEP 4
  ├─ 더 고치기 → STEP 3
  ├─ 인쇄
  ├─ 재생
  └─ 다른 슬롯 편집
~~~

완성 화면에서 다시 편집으로 돌아갈 수 있으므로 **wizard처럼 보이지만 실제로는 순환 가능한 state machine**이다.

# 3. 상단 진행 영역

상단 4단계는 단순 breadcrumb가 아니다.

- 완료 단계
- 현재 단계
- 아직 진행하지 않은 단계

를 동시에 표현한다.

우측 상태 배지는 조, 조표, 박자 등 현재 음악 상태를 요약한다.

즉 상단은 다음 두 질문에 답한다.

~~~text
어디까지 왔는가?
+
지금 어떤 곡을 만들고 있는가?
~~~

향후에는 너무 길어지지 않는 범위에서 현재 슬롯과 저장 여부까지 보조적으로 표현할 수 있다.

---

# 4. Step 1의 실제 교육 구조

장조/단조 카드는 이름, 청감 특징, 분위기 언어, 즉시 비교 청음을 한 묶음으로 제공한다.

## 장점

- 음악 개념을 텍스트 정의로만 시작하지 않음
- 청각적 차이를 먼저 경험 가능
- 학생이 창작 조건을 직접 선택
- 선택 결과가 Step 2의 조 후보와 연결

## 위험

최초 카드의 인상이 강해 장조=즐거움, 단조=슬픔으로 고정될 수 있다.

권장 표현은 “자주 이렇게 느껴질 수 있어”처럼 가능성 언어를 쓰는 것이다.

---

# 5. 곡 서랍은 사실상 버전 관리 UI

장조 2곡 + 단조 2곡이라는 슬롯 제한은 저장 기능보다 교육적으로 더 중요하다.

학생에게 하나만 만들지 말고, 비교하고, 고치고, 발표할 하나를 선택하도록 유도한다.

최소 상태:

~~~text
EMPTY
SAVED
CURRENT
PRESENTATION
~~~

상태가 중첩될 수 있으므로 구현에서는 단일 enum보다 플래그 분리가 안전하다.

~~~ts
type SongSlot = {
  song: Song | null
  isCurrent: boolean
  isPresentation: boolean
}
~~~

---

# 6. Step 2는 조 이론보다 재료 선택 화면

조 카드들은 같은 장조라도 실제 pitch set과 조표가 달라진다는 사실을 비교하게 한다.

각 카드가 동일한 순서로 조 이름, 조표, 음계, 으뜸음, 나란한조, 설명, 청음을 제공하므로 비교가 쉽다.

다만 “어느 음에서 시작하느냐에 따라 조 이름이 달라진다”는 표현은 시작음이 아니라 중심음/으뜸음으로 수정해야 한다.

---

# 7. Step 3의 리듬 모델 재해석

완성 화면의 표기 규칙:

- 음이름 = 새 음이 시작됨
- – = 앞 음이 계속됨
- · = 쉼

따라서 그리드는 단순 pitch cell보다 **pitch-time onset grid**로 보는 것이 더 정확하다.

## 7.1 시간 해상도

4/4박자 × 4마디, 한 마디 4칸. 최소 시간 단위는 1박이다.

## 7.2 음 길이

새 음 이후 다음 onset까지 지속되는 구조라면 다음 길이를 표현할 수 있다.

- 1박: 4분음표 길이
- 2박: 2분음표 길이
- 3박: 점2분음표 길이
- 4박: 온음표 길이

예:

~~~text
도 – – –  = 4박 지속
도 – 미 –  = 2박 + 2박
도 – – 미  = 3박 + 1박
~~~

이것은 단순 한 박 한 음보다 훨씬 좋은 설계다.

## 7.3 미확인

별도 쉼표 입력 버튼이 화면에 보이지 않으므로 ·를 만드는 정확한 인터랙션은 현재 자료만으로 확인되지 않는다.

## 7.4 권장 내부 모델

~~~ts
type NoteEvent = {
  pitch: number
  onset: number
  duration: number
}
~~~

UI가 16칸이어도 저장 구조까지 셀 배열로 고정하면 8분음표 확장이 어렵다.

# 8. 그리드는 음악 구조를 공간 구조로 변환

세로 = pitch  
가로 = time  
마디 경계 = grouping

장점:

- 마디 경계 인식
- 반복 패턴 발견
- 높낮이 변화 직관적 인식
- 태블릿 터치 적합

한계:

- 실제 음표 모양 학습 약함
- 8분음표 이하 subdivision 표현 어려움
- 붙임줄/점음표 기보와 직접 연결되지 않음

따라서 최종 결과에 실제 오선보 view를 연결하는 것이 중요하다.

---

# 9. 마디별 역할은 작곡 규칙이 아니라 scaffolding script

1. 씨앗 심기
2. 거의 그대로
3. 달라지기
4. 문 닫기

는 학생 행동 언어로 번역한 학습용 template이다.

| 학생용 언어 | 음악적 개념 후보 |
|---|---|
| 씨앗 | motive / initial idea |
| 거의 그대로 | repetition / slight variation |
| 달라지기 | contrast / development |
| 문 닫기 | closure / cadence |

이것을 보편적인 4마디 작곡 법칙처럼 가르치기보다 “처음 만들 때 써 보는 한 가지 방법”으로 표현하는 편이 정확하다.

---

# 10. 변형 버튼은 composition grammar를 직접 조작하게 함

- 1마디 → 2마디 복사
- 2마디 끝음만 바꾸기
- 3마디 위아래 뒤집기

는 반복, 작은 변화, contour transformation을 말이 아니라 operation으로 수행하게 한다.

다만 위아래 뒤집기가 grid mirror인지 melodic inversion인지 현재 화면만으로는 확인할 수 없다.

---

# 11. 화음 선택은 주요3화음 학습과 직접 연결

다장조에서 I=C-E-G, IV=F-A-C, V=G-B-D를 마디마다 선택한다.

장점:

- 화음 기능을 소리와 연결
- 왼손/오른손 역할로 실제 연주 가능
- 마디 단위 harmonic context 제공
- 가락 피드백 기준 생성

향후 한 마디 안 화음 변화까지 확장하려면 내부 구조는 bar당 chord 하나보다 ChordEvent 배열이 낫다.

---

# 12. 화음 피드백 엔진의 음악적 위험

현재 예시:

- I(C-E-G) 위 A → G 추천
- V(G-B-D) 위 F → G 추천

교육적으로 주요 3화음 구성음을 체감하게 하는 장점은 있다.

그러나 화음 밖 음을 모두 오류처럼 다루면 지나치게 거칠다.

특히 G-B-D 위 F는 G7의 7음으로 기능할 수 있어 C로 해결되는 전형적 긴장음이 될 수 있다.

초등 단계에서 V7을 직접 가르치지 않더라도 시스템은 이를 “틀림”으로 단정하기보다:

- 안정적인 화음 음
- 자연스럽게 지나가는 음
- 긴장감을 만드는 음
- 끝맺음에서 확인할 음

처럼 **stability/tension** 관점으로 분류하는 편이 낫다.

---

# 13. 화음 음은 언제 놓아도 어울린다는 표현

입문 설명으로는 쉽지만 절대적이다.

화음 구성음이라도 도약, 음역, 반복, voice leading에 따라 어색할 수 있다.

권장:

> 이 화음에서 가장 안정적으로 들리는 음이야.

---

# 14. 끝맺음 피드백

현재 문 닫기 안내는:

- 마지막 음을 으뜸음
- V 다음 I
- 길게 지속

을 안정된 끝과 연결한다.

좋은 scaffold지만 다른 끝맺음을 오류로 만들면 안 된다.

권장:

> 으뜸음으로 끝내면 가장 안정적으로 끝난 느낌을 만들기 쉽다. 다른 음은 열린 느낌을 만들 수 있다.

# 15. melodic contour는 좋은 중간 표현

가락이 그린 그림은 소리와 오선보 사이의 bridge다.

~~~text
소리
↕
가락 윤곽
↕
오선보
~~~

현재는 첫 두 단계만 있다.

자체 구현에서는 contour를 없애지 말고 오선보와 함께 유지하는 것이 좋다.

---

# 16. a / a′ 표기의 의미

각 마디에 a, a, a′, -를 붙이는 것은 전체 곡의 대형식보다 **마디 단위 동기/패턴 유사성**에 가깝다.

따라서 다음을 구분해야 한다.

### 동기/마디 관계
a → 같은 아이디어  
a′ → 비슷하지만 변형  
b → 다른 아이디어

### 큰 형식
AB, ABA 등

“내 곡의 형식”이라는 표현은 쉬우나 큰 형식과 동일 개념처럼 섞이지 않게 해야 한다.

---

# 17. 형식 판정 알고리즘 추정

현재 사례는 1마디 A, 2마디 A, 3마디 F, 4마디 empty인데 a, a, a′, -로 나타난다.

가능한 구조:

~~~text
bar2 === bar1 → a
similarity(bar1, barN) >= threshold → a′
else → b
~~~

정확한 threshold는 미확인이다.

권장 feature:

- onset pattern
- pitch contour
- interval sequence
- exact pitch match ratio
- rhythm match ratio

단순 음 개수만 비교하면 오판 가능성이 높다.

---

# 18. 곡 서랍의 음 N개 의미

현재 세 마디에 각각 하나의 새 pitch가 시작되고 곡 서랍에는 “음 3개”라고 표시된다.

따라서 음 N개는 서로 다른 pitch class 수보다 **note onset event 수**일 가능성이 높다.

표현은 “음표 3개” 또는 “새로 시작한 음 3개”가 더 명확할 수 있다.

---

# 19. 완성 화면은 reflection screen

완성 화면은 단순 결과가 아니라:

- 마디별 정보
- contour
- 반복/변형 관계
- 미완성 경고
- 끝맺음 조언
- 피아노 연주법
- 다시 고치기
- 인쇄
- 곡 서랍 비교

를 제공한다.

즉 역할은 Result + Analysis + Reflection + Transfer to performance다.

# 22. 접근성

# 23. 2022 개정 교육과정 정합성

5~6학년 창작에서는 느낌/아이디어 표현, 기초 기보와 조건에 따른 변경, 음악 요소를 활용한 간단한 음악 만들기, 디지털 매체 활용과 공유를 강조한다.

5~6학년 음악 요소에는 박/박자, 여러 리듬꼴, 음이름/계이름, 장음계/단음계, 주요3화음, 다양한 소리의 어울림, 형식, 셈여림·빠르기 변화 등이 포함된다.

## 강하게 다루는 것

- 4/4박자
- 음이름/계이름
- 장음계/단음계
- 주요3화음
- 소리의 어울림
- 간단한 음악 만들기
- 부분 반복/변형
- 디지털 매체

## 부분적으로 다루는 것

- 리듬꼴
- 형식
- 기초 기보

## 거의 다루지 않는 것

- 셈여림 변화
- 빠르기 변화
- 8분음표 이하 리듬 세분
- 실제 오선보 기보
- 협력 창작

따라서 교육과정 정합성은 높지만 전체 요소를 포괄하는 도구는 아니다. 한 차시/프로젝트의 범위를 명확히 하는 것이 좋다.

# 24. 실제로 잘 해결한 교육 문제

## 빈 악보 공포
4마디 틀, 마디 역할, 예시, 복사 버튼으로 해결.

## 반복만 하는 단조로운 곡
끝음 변경, 뒤집기, a/a′ 분석으로 해결.

## 무작위 음 찍기
조 제한, 화음 안내, context help로 해결.

## 결과를 설명하지 못함
contour, 형식 기호, 화음 정보로 해결.

## 디지털 놀이로 끝남
피아노 연주, 발표곡 선택, 인쇄로 해결.

# 26. 권장 canonical model

~~~ts
type Song = {
  id: string
  mode: "major" | "minor"
  key: KeyDefinition
  meter: { numerator: 4, denominator: 4 }
  tempo: number
  noteEvents: NoteEvent[]
  chordEvents: ChordEvent[]
  metadata: {
    slotType: "major-1" | "major-2" | "minor-1" | "minor-2"
    presentation: boolean
  }
}

type NoteEvent = {
  pitch: number
  onsetBeat: number
  durationBeats: number
}

type ChordEvent = {
  onsetBeat: number
  durationBeats: number
  degree: 1 | 4 | 5
}
~~~

UI의 16칸은 이 모델을 편집하는 view일 뿐이어야 한다.

# 27. 핵심 설계 원칙

1. 음악 개념을 조작으로 번역한다.
2. 한 번에 선택할 자유도를 제한한다.
3. 소리를 즉시 들려준다.
4. 반복과 변형을 버튼으로 만든다.
5. 오답 대신 수정 가능한 피드백을 준다.
6. 결과를 시각적 구조로 다시 보여 준다.
7. 여러 결과를 비교하게 한다.
8. 디지털 결과를 실제 연주로 연결한다.
9. 완성 화면도 다시 수정 가능한 상태로 둔다.
10. 내부 데이터는 UI보다 더 일반적으로 설계한다.
