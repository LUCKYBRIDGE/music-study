# 화면 캡처 기반 UI·UX 분석

- 대상: **작곡소 — 장조·단조로 네 마디 노래 만들기**
- 분석 자료: 2026-11-11 제공된 4개 화면 캡처
- 증거 수준: **Observed**
- 목적: DOM 텍스트만으로는 확인하기 어려운 시각적 계층, 색상 의미, 배치, 화면 전환을 보완한다.

---

## 1. 전체 시각 언어

페이지는 전체적으로 따뜻한 아이보리/크림색 배경 위에 흰색 카드가 놓이는 구조다.

### 주요 시각 특징

- 화면 최상단에 서비스명 **작곡소**
- 바로 옆에 **장조·단조로 네 마디 노래 만들기 · 5학년 음악**
- 우측에는 현재 선택 상태를 요약하는 작은 배지
- 그 아래 4단계 진행 탭이 화면 폭을 거의 동일하게 분할
- 본문은 큰 흰색 카드와 얇은 테두리 중심
- 버튼은 기능 유형별로 색을 다르게 사용
- 긴 설명문보다 짧은 문장, 굵은 핵심어, 직접 실행 버튼을 함께 배치

화려한 장식보다 **상태와 기능을 색으로 구분하는 교과용 도구형 UI**에 가깝다.

---

## 2. 공통 Progress Navigation

네 단계가 항상 상단에 유지된다.

1. 장조? 단조?
2. 어느 조로
3. 가락 짓기
4. 완성곡

### 상태 표현

캡처에서 세 가지 상태가 시각적으로 분리된다.

- **완료 단계**: 초록 계열 번호/강조
- **현재 단계**: 빨강 계열 테두리와 번호
- **미진행 단계**: 연한 회색/베이지

이 방식의 장점은 학생이 숫자를 읽지 않아도 현재 위치를 쉽게 구분한다는 것이다.

### 재사용 패턴

~~~text
완료 = 성공/지나온 단계
현재 = 지금 해야 할 일
미진행 = 아직 열리지 않은 단계
~~~

색상만으로 끝내지 않고 숫자와 텍스트를 함께 제공하므로 의미 중복이 있다.

---

# 3. Step 1 — 장조? 단조?

## 3.1 화면 구성

상단 설명 아래에 장조와 단조 카드가 **좌우 대칭 2열**로 배치된다.

### 장조 카드

- 좌측
- 붉은/금색 계열 액션 버튼
- 장조
- 長調 · major — 으뜸음이 도
- 분위기 chip: 밝다, 씩씩하다, 즐겁다, 탁 트인다
- 이 느낌 듣기
- 장조로 만들기 →

### 단조 카드

- 우측
- 보라 계열 액션 버튼
- 단조
- 短調 · minor — 으뜸음이 라
- 분위기 chip: 어둡다, 그립다, 차분하다, 비장하다
- 이 느낌 듣기
- 단조로 만들기 →

## 3.2 색상 의미

이 화면부터 **장조와 단조에 별도의 UI 식별 색**이 배정된다.

- 장조: 적색/주황 계열
- 단조: 보라 계열

이 색은 이후 **내 곡 서랍**의 슬롯 태그와 버튼에도 반복된다.

즉 색상이 단순 장식이 아니라 **mode identity** 역할을 한다.

### 좋은 점

사용자가 뒤 화면으로 이동해도 카드 색만 보고 장조/단조 맥락을 빠르게 인식한다.

### 주의점

장조=빨강/단조=보라가 음악적 의미로 오해되지 않도록, 색은 어디까지나 UI 식별에만 사용해야 한다.

---

# 4. Step 1 하단 — 내 곡 서랍

첫 단계부터 작품 저장 상태가 보인다.

## 구조

4개의 동일 크기 카드:

- 장조 ①
- 장조 ②
- 단조 ①
- 단조 ②

빈 슬롯은 **빈 칸**과 **여기에 만들기 →**만 보여 준다.

곡이 있는 슬롯은:

- 조 이름
- 음 개수
- 현재 편집 중인 곡 여부
- 듣기
- 고치기
- 발표곡 지정
- 비우기

가 노출된다.

## 중요한 UX

### 저장이 사후 기능이 아니다

학생은 작곡을 시작하기 전부터 “곡을 여러 개 만들 수 있다”는 것을 안다.

따라서 작업의 mental model이 **한 곡을 완성해야 한다**가 아니라 **여러 곡을 만들어 비교할 수 있다**로 바뀐다.

### 현재 곡 강조

현재 편집 중인 슬롯은 푸른 테두리로 강조된다.

즉:

- mode 색: 장조/단조의 분류
- 파란 테두리: 현재 편집 상태
- 별 버튼: 발표 선택 상태

가 서로 다른 의미를 담당한다.

한 색에 너무 많은 의미를 몰아넣지 않은 점이 좋다.

# 5. Step 1 하단 — QR 접속 카드

별도의 넓은 카드 안에:

- QR 코드
- 태블릿에서 바로 열기
- 실제 URL
- 기기 저장 안내
- QR 확대 안내

가 함께 배치된다.

## 역할

이 요소는 콘텐츠가 아니라 **교실 진입 인프라**다.

교사가 빔 화면으로 띄워 놓으면 학생이 QR을 찍어 바로 접속하는 상황을 고려한 것으로 보인다.

### 재사용 가치

교육 웹에서는 URL 복사보다 QR 진입이 중요하므로 분석 대상에서 별도 기능으로 취급해야 한다.

---

# 6. Step 2 — 어느 조로

## 6.1 카드형 조 선택

화면에는 다장조, 사장조, 바장조가 3열 카드로 배치된다.

각 카드의 정보 순서는 거의 동일하다.

1. 조 이름 + 영문 음이름
2. 조표 정보
3. 계이름/음이름 배열
4. 으뜸음
5. 나란한조
6. 짧은 성격 설명
7. 음계 듣기
8. 이 조로 짓기

### 좋은 점

모든 카드가 같은 정보 순서를 가져 비교가 쉽다.

학생은 조 이름보다 아래의 조표·사용 음·나란한조 차이를 시각적으로 비교할 수 있다.

## 6.2 조표 설명 카드

조 카드 아래에는 전체 폭을 차지하는 별도 설명 영역이 있다.

핵심은 **조표는 장식이 아니라 온음·반음 자리를 지키는 표시**라는 인과관계를 제공한다는 점이다.

조표를 별도 이론 페이지에서 먼저 가르치는 것이 아니라 **학생이 조를 선택하는 순간 필요한 만큼 설명**한다.

이는 contextual teaching 패턴이다.

---

# 7. Step 3 — 가락 짓기

가장 복잡한 화면이지만 세 영역으로 분할되어 있다.

~~~text
[마디 역할 카드 4개]

[화음 + 음높이/시간 그리드] [현재 마디 설명]

[재생/변형 컨트롤]
~~~

## 7.1 마디 역할 카드

4개 카드가 상단에 가로로 배치된다.

- 1마디 — 씨앗 심기
- 2마디 — 거의 그대로
- 3마디 — 달라지기
- 4마디 — 문 닫기

현재 마디는 붉은 테두리로 강조된다.

각 카드 상단에 작은 진행 상태 원이 있어 해당 마디가 채워졌는지를 알려 준다.

### UX 효과

4마디라는 음악 형식을 화면의 **4개 물리적 영역**으로 그대로 번역한다.

음악 형식이 추상 설명이 아니라 인터페이스 구조가 된다.

---

## 7.2 화음 선택 영역

각 마디 위에 I / IV / V 버튼이 있다.

선택된 화음은 진한 파란색으로 채워진다.

그 아래에는 실제 화음 구성음이 표시된다.

예:

- 도·미·솔
- 파·라·도
- 솔·시·레

### 색상 설계

여기서는 장조의 붉은 identity 색을 쓰지 않고 **파란색을 선택 상태 색**으로 쓴다.

이는 적절하다. 붉은색이 장조와 주요 진행 버튼에 이미 사용되므로, 화음의 현재 선택을 별도 semantic color로 분리한다.

---

# 8. Pitch-Time Grid 상세

캡처에서 그리드는 왼쪽의 음높이 라벨과 16개의 시간 위치로 구성된다.

### 세로축

예:

- 도↑
- 시
- 라
- 솔
- 파
- 미
- 레
- 도
- 시↓
- 라↓

음이름 C, D, E 등의 보조 표기가 함께 있다.

### 가로축

4마디 × 4박.

각 마디의 1박은 폭이 넓고, 2·3·4박은 상대적으로 좁아 보이는 시각 구조가 사용된다.

이는 단순 균등 16칸이라기보다 **마디 경계를 강조하기 위한 layout**이다.

### 장점

- 마디의 시작점이 한눈에 보임
- 4마디 구조가 깨지지 않음
- 학생이 지금 어느 마디의 어느 박인지 찾기 쉬움

### 구현 시 주의

데이터에서는 모든 beat를 균등한 시간 단위로 저장하고, 시각적 폭 차이는 CSS layout으로만 처리해야 한다.

---

# 9. 우측 Context Panel

작곡 화면 오른쪽에는 현재 마디에 대한 설명 패널이 붙는다.

예:

- 1마디 — 씨앗 심기
- 지금 화음은 I (으뜸화음)
- 현재 화음의 구성음
- 시작음에 대한 조언
- 이 마디만
- 화음 소리

### 핵심 패턴

사용자에게 모든 도움말을 한 번에 보여주는 것이 아니라 **현재 선택된 마디의 맥락에 맞는 도움말만 보여 준다.**

즉 context-sensitive help다.

초등학생용 복잡한 제작 도구에서 매우 유용한 설계다.

---

# 10. 화음 피드백 카드

우측 설명 아래에 별도의 **화음과 맞는지** 카드가 있다.

초기 상태에서는 음을 놓아 보도록 행동을 유도하고, 하단 범례는:

- 화음 음
- 지나가는 음
- 부딪히는 음

으로 나뉜다.

### 좋은 점

피드백 영역이 그리드 안에 섞이지 않고 별도 카드로 존재한다.

따라서 그리드는 **입력**, 우측은 **해석**이라는 역할 분리가 명확하다.

---

# 11. 재생 컨트롤의 색상 의미

그리드 아래 주요 재생 버튼:

- 처음부터 — 적색
- 가락만 — 초록
- 화음만 — 파랑
- 멈춤 — 회색
- 반주 켬 — 초록 테두리
- 느리게 — 중립색

각 소리 층(layer)에 색을 부여한다.

### 재사용 가능 패턴

~~~text
전체곡 = primary
melody = green
harmony = blue
transport stop = gray
option/toggle = outline
~~~

학생이 텍스트를 반복해 읽지 않아도 색상과 위치로 기능을 학습할 가능성이 높다.

---

# 12. 변형 도구 영역

재생 버튼 아래에는:

- 1마디 → 2마디 복사
- 2마디 끝음만 바꾸기
- 3마디 위아래 뒤집기
- 예시 넣기
- 되돌리기
- 전부 지우기
- 완성곡 보기

가 배치된다.

### 시각적 계층

- 자동 변형: 흰색/중립 버튼
- 예시: 금색
- 되돌리기: 비활성 상태에서는 매우 옅게
- 전부 지우기: 중립
- 다음 단계: 보라색

즉 **제작 도구 / 보조 기능 / 진행 버튼**을 시각적으로 구분한다.

# 13. Step 4 — 완성곡

완성 화면은 편집기보다 정보량이 줄어든다.

왼쪽 큰 카드와 오른쪽 연주 안내 카드로 분할된다.

## 13.1 내 곡 요약

상단에는:

- 내 곡
- 다장조
- 4/4박자
- 네 마디

가 나타난다.

그 아래 마디별:

- 화음 로마 숫자
- 음 이름
- 비어 있는 박

을 텍스트 형태로 보여 준다.

이것은 악보를 읽지 못하는 학생도 자신의 음악을 문자 정보로 확인할 수 있게 한다.

---

## 13.2 가락이 그린 그림

4개 마디 박스를 가로로 배치하고, 실제 가락의 높이에 따라 선의 높이가 달라진다.

즉 곡을 **melodic contour**로 요약한다.

### 교육적 가치

오선보 읽기 이전에도:

- 올라갔다
- 내려갔다
- 같은 높이로 반복됐다
- 크게 뛰었다

를 시각적으로 이해할 수 있다.

### 개선 가능성

향후 자체 도구에서는 이 contour와 실제 오선보를 함께 보여 주는 것이 좋다.

~~~text
가락 그림      실제 악보
─────────      ♩ ♪ ♩ ...
~~~

학생이 두 표현 사이의 대응을 학습할 수 있다.

---

# 14. 형식 분석 카드

가락 윤곽 아래 4개의 작은 카드가 있다.

캡처에서는:

- a — 씨앗
- a — 그대로 반복
- a′ — 조금 바꿔 반복
- - — 비어 있음

처럼 표현된다.

### 중요한 설계

학생이 만든 결과를 **형식 기호(a, a′)**로 번역한다.

~~~text
학생의 실제 음 입력
        ↓
반복/변형 관계
        ↓
a / a′ 같은 음악 형식 언어
~~~

로 연결한다.

이 패턴은 음악 요소 학습에서 활용 가치가 높다.

---

# 15. 미완성 상태도 완성 화면에서 설명한다

4마디가 모두 채워지지 않은 경우, 아직 형식이 완성되지 않았음을 설명하고 네 마디를 채우면 형식 분석이 나타난다고 안내한다.

### 좋은 점

완성 화면 진입 자체를 막기보다 **현재 상태를 보여 주고 부족한 조건을 설명**한다.

이는 hard validation보다 soft validation에 가깝다.

교육용 창작 도구에는 이쪽이 더 적합하다.

---

# 16. 피아노 연주 안내

오른쪽 패널에는:

- 이 곡의 도는 피아노 C건반
- 흰건반 이동 순서
- 왼손 마디별 화음
- 오른손은 가락

등을 설명한다.

### 역할

디지털 작곡 결과를 화면 안에서 끝내지 않고 **실제 악기 연주 활동**으로 연결한다.

따라서 완성 화면은 단순 result screen이 아니라 **디지털 창작 → 실제 수행**의 bridge다.

# 19. 개선해서 가져올 것

## A. 오선보 추가

현재 contour는 이해하기 쉽지만 실제 기보 학습으로 연결되지 않는다.

권장: **가락 그림 / 오선보**를 토글하거나 동시에 제공.

## B. 계이름/음이름 표시 개선

한글 계이름과 영문 음이름이 한 줄에 섞이면 어린 학생에게 복잡해 보일 수 있다.

권장:

- 계이름 중심 보기
- 음이름 함께 보기

토글.

## C. 색상 의존성 줄이기

화음음/지나가는음/부딪히는음을 색만으로 구분하지 않고 아이콘이나 패턴을 추가한다.

## D. Step 3의 밀도 완화

가락 짓기 화면은 다른 단계보다 정보량이 급격히 많아진다.

태블릿에서는:

- 기본 편집
- 도움말
- 고급 변형

을 접기/펴기로 분리하는 방안을 검토할 수 있다.

# 20. 화면 캡처에서 새롭게 확인된 핵심 결론

텍스트 DOM만 보았을 때보다 실제 캡처에서는 이 서비스가 **색상과 공간 배치를 학습 구조 자체로 사용**한다는 점이 더 분명하다.

특히:

~~~text
4단계 학습 흐름
+
4마디 음악 형식
+
장조/단조 mode identity
+
현재 마디 context help
+
완성 후 contour/form 분석
~~~

이 서로 독립된 기능이 아니라 하나의 시각 시스템으로 연결되어 있다.

따라서 자체 음악 교육 앱을 설계할 때는 단순히 기능을 복사하는 것보다 **음악 구조를 화면 구조로 직접 번역하는 방식**을 핵심 원칙으로 가져오는 것이 좋다.
