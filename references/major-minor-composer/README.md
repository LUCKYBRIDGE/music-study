# 장조·단조 네 마디 작곡소 분석

- 분석 대상: **작곡소 — 장조·단조로 네 마디 노래 만들기**
- URL: https://leixlix-pixel.github.io/toolbox/major-minor-composer.html
- 분석일: 2026-11-11
- 대상 학년 표기: 5학년 음악
- 분석 성격: 실제 배포 페이지의 화면·DOM·상호작용을 기준으로 한 기능/교육/UI 분석
- 내부 소스 확인 여부: **미확인**. 따라서 라이브러리, 실제 함수명, 서버 구현은 단정하지 않음.

---

## 1. 한 문장 정의

이 도구는 자유 작곡기가 아니라, 학생에게 선택지를 단계적으로 제한하면서

**장·단조 청음 → 조 선택 → 4마디 가락 창작 → I·IV·V 계열 화음과의 관계 확인 → 수정 → 발표곡 선택**

까지 안내하는 **초등용 guided composer**이다.

핵심 가치는 악보 편집 기능의 많고 적음보다 **작곡 과정을 학습 가능한 작은 행동으로 분해한 것**에 있다.

---

## 2. 전체 사용자 흐름

### Step 1. 장조? 단조?

학생은 장조와 단조의 설명을 읽고 같은 성격의 예시를 들어 본다.

주요 UI:

- 장조 카드
- 단조 카드
- `🔊 이 느낌 듣기`
- `장조로 만들기 →`
- `단조로 만들기 →`

교육적 역할:

- 설명보다 먼저/함께 소리를 들으며 조성의 느낌을 비교
- 장조/단조를 이후 모든 작곡 설정의 첫 번째 결정으로 만듦
- 추상 개념을 선택 가능한 두 상태로 단순화

주의:

- 장조=밝음, 단조=어두움으로 고정되지 않도록 표현 보완 필요
- “이번 예시에서 어떤 음을 바꾸었는지”를 명확히 해야 일반적인 장·단조 차이로 오해하지 않음

---

### Step 2. 어느 조로

실제 화면에서 단조 선택 시 다음과 같은 조가 제시된다.

- 가단조 Am
- 마단조 Em
- 라단조 Dm

각 카드에는 대략 다음 정보가 포함된다.

- 조 이름
- 조표
- 사용 음
- 으뜸음
- 나란한조
- 짧은 음색/특징 설명
- `🔊 음계 듣기`
- `이 조로 짓기 →`

좋은 점:

1. 조 이름만 제시하지 않고 **사용 가능한 음 집합**을 바로 보여 준다.
2. 조표를 작곡 전에 확인시켜, 뒤의 그리드에서 왜 특정 음만 사용할 수 있는지 연결한다.
3. 나란한조를 “쓰는 음이 같고 중심이 다르다”는 방식으로 설명하려는 의도가 좋다.
4. 음계를 바로 들을 수 있어 시각 정보와 청각 정보가 연결된다.

보완점:

- “어느 음에서 시작하느냐”가 아니라 “어느 음을 으뜸음/중심음으로 삼느냐”로 설명해야 정확하다.
- 계이름과 음이름을 분리해서 보여 주는 편이 좋다.
- 자연단음계와 단조 V화음에서 나타나는 올림7음의 관계를 설명해야 한다.

## 3. 작곡 화면: 핵심 UX

작곡 입력부는 사실상 **초등학생용 pitch-time grid**이다.

### 세로축

음높이.

예: 라↑, 솔, 파, 미, 레, 도, 시, 라, 솔↓, 파↓

### 가로축

시간.

4/4박자 × 4마디로 보이며, 총 16개의 박 위치가 존재한다.

즉 학생은 오선보를 직접 다루지 않고도

- 위/아래 = 음높이
- 왼쪽/오른쪽 = 시간

으로 멜로디를 입력할 수 있다.

이 모델의 장점:

- 오선보 기보 능력이 부족해도 작곡 가능
- 터치 기반 태블릿에서 입력이 쉽다
- 음높이 변화가 시각적으로 곧바로 보인다
- 4마디라는 제한 때문에 과제가 지나치게 커지지 않는다

한계:

- 현재 구조만으로는 8분음표, 점음표, 쉼표 길이 같은 복합 리듬 표현이 어렵다.
- 따라서 이 도구의 중심은 **리듬 작곡보다는 음높이·가락·화음 관계 학습**이다.

---

## 4. 4마디 구조를 학습 행동으로 번역한 방식

이 서비스의 가장 좋은 설계다.

| 마디 | 학생용 표현 | 음악적 역할 |
|---|---|---|
| 1마디 | 씨앗 심기 | 동기 제시 |
| 2마디 | 거의 그대로 | 반복 + 작은 변형 |
| 3마디 | 달라지기 | 대조/발전 |
| 4마디 | 문 닫기 | 종지/완결 |

중요한 점은 설명으로 끝내지 않고 실제 버튼으로 변환했다는 것이다.

- `1마디 → 2마디 복사`
- `2마디 끝음만 바꾸기`
- `3마디 위아래 뒤집기`

즉,

**음악 개념 → 조작 명령 → 소리로 확인 → 다시 수정**

의 루프가 만들어져 있다.

이 패턴은 다른 음악 교육 도구에 적극적으로 재사용할 가치가 있다.

---

## 5. 화음 구조

마디마다 화음을 선택할 수 있다.

단조 예시에서는:

- ⅰ
- ⅳ
- Ⅴ

가 사용되고, 각 마디 아래에 구성음을 알려 준다.

가단조의 예:

- ⅰ: 라·도·미
- ⅳ: 레·파·라
- Ⅴ: 미·솔♯·시

좋은 점:

- 학생이 “가락”과 “반주”를 분리해서 생각하게 한다.
- 화음 이름만 보여 주지 않고 구성음을 함께 제시한다.
- 마디별 화음이 바뀌면서 같은 음도 맥락에 따라 다르게 들릴 수 있음을 경험하게 한다.

특히 왼손 화음과 오른손 가락을 나누어 피아노로 연주할 수 있도록 설명한 점은 디지털 결과를 실제 연주로 연결한다.

---

## 6. 피드백 구조

현재 화면에는 학생이 배치한 음과 화음의 관계를 검사하는 피드백이 존재한다.

표현 범주:

- 화음 음
- 지나가는 음
- 부딪히는 음

그리고 특정 위치에 대해

- 몇 마디
- 몇 박
- 현재 음
- 현재 화음
- 대체 후보

를 제시한다.

이 구조는 좋은 formative feedback 모델이다.

### 권장 발전 방향

단순한 `pitch ∈ chord tones` 판정만으로 끝내지 않고 다음 정보를 함께 고려해야 한다.

1. 강박/약박
2. 앞 음과 뒤 음
3. 순차 진행 여부
4. 반복음 여부
5. 이웃음/경과음 가능성
6. 마디 끝 및 곡 마지막 위치
7. 으뜸음으로 해결되는지 여부

예:

```text
C - D - E
```

C화음에서 D는 화음 구성음이 아니지만, 약박에서 C와 E를 연결하면 자연스러운 경과음일 수 있다.

따라서 교육용 피드백은:

- ● 화음 구성음
- ○ 자연스러운 지나가는 음
- △ 다시 들어볼 음

처럼 단계적으로 처리하는 편이 적합하다.

## 7. 재생 컨트롤

확인된 기능:

- 처음부터
- 가락만
- 화음만
- 멈춤
- 반주 켬
- 느리게
- 이 마디만
- 화음 소리
- 완성곡 들어보기

장점은 **재생 범위를 세분화했다는 것**이다.

학생은 곡 전체만 반복해서 듣는 것이 아니라:

- 음계
- 화음
- 한 마디
- 가락
- 반주
- 전체곡

을 따로 들을 수 있다.

이는 음악 요소를 분리하여 듣는 훈련에도 유용하다.

## 8. 수정 지원

확인된 기능:

- 예시 넣기
- 되돌리기
- 전부 지우기
- 특정 마디 복사
- 끝음만 변경
- 위아래 뒤집기

여기서 중요한 UX 원칙은 학생에게 “창작하라”고만 하지 않고 **변형 도구를 직접 제공한다는 것**이다.

창작 지원 기능을 세 범주로 정리할 수 있다.

### 생성

- 예시 넣기
- 빈 슬롯에서 새 곡 만들기

### 변형

- 마디 복사
- 끝음 변경
- 음형 뒤집기

### 복구

- 되돌리기
- 전체 삭제

향후 자체 도구에서도 이 세 범주는 유지할 가치가 높다.

## 9. 작품 저장과 발표

페이지에는 “내 곡 서랍” 개념이 있다.

현재 구조:

- 장조 ①
- 장조 ②
- 단조 ①
- 단조 ②

각 작품에 대해:

- 듣기
- 고치기
- 발표곡 선택
- 비우기

가 가능하다.

### 교육적으로 좋은 이유

한 곡을 만들고 즉시 제출하는 것이 아니라

**생성 → 비교 → 수정 → 선택 → 발표**

의 창작 과정을 경험하게 한다.

`⭐ 이걸로 발표` 버튼은 단순 favorite 기능이 아니라 학생이 여러 결과 중 하나를 스스로 선택하게 하는 성찰 장치다.

---

## 10. 저장 방식에 대한 관찰

페이지에는 “이 태블릿에 저장”, “창을 닫았다 다시 열어도 그대로 있다”는 안내가 있다.

따라서 브라우저 로컬 저장소 계열을 사용하는 구조일 가능성이 높다.

그러나 실제 소스를 확인하지 않았으므로:

- localStorage
- IndexedDB
- 다른 browser storage

중 무엇인지는 확정하지 않는다.

서버 계정 없이 동일 기기에 작품을 유지시키는 설계는 교실 환경에서 장점이 있다.

장점:

- 로그인 불필요
- 개인정보 부담 감소
- 즉시 시작

한계:

- 다른 기기로 이동하기 어렵다
- 교사가 일괄 수집하기 어렵다
- 브라우저 데이터 삭제 시 소실 가능성
- 학생별 작품 관리가 어렵다

## 11. QR 활용

현재 URL을 태블릿에서 바로 열 수 있도록 QR을 제공한다.

이 기능의 역할은 작품 공유라기보다 **수업 진입 비용을 낮추는 것**에 가깝다.

교실에서는 긴 URL 입력 대신 QR로 바로 진입할 수 있어 중요하다.

향후 자체 서비스에서는 다음을 구분할 필요가 있다.

- 서비스 접속 QR
- 학생 작품 공유 QR
- 교사 제출함 QR

## 12. 완성곡 화면

완성 단계에서는:

- 내가 만든 가락의 높낮이 그림
- 전체 듣기
- 더 고치기
- 인쇄
- 피아노 연주 안내
- 반주와 함께 듣기
- 가락만 듣기

등이 제공된다.

좋은 점은 “완성”이 수정 불가능한 종착점이 아니라는 것이다.

`← 더 고치기`

가 명시적으로 제공되어 창작 과정이 순환 구조가 된다.

## 13. 이 도구의 강점 요약

### 교육

- 장·단조 청음과 창작을 연결
- 음악 개념을 실제 조작으로 변환
- 4마디라는 적절한 제약
- 반복/변형/대조/종지의 구조 제공
- 화음과 가락 관계에 대한 즉시 피드백
- 여러 작품을 비교하고 발표작을 선택

### UX

- 단계별 공개
- 큰 행동 단위의 버튼
- 짧은 설명 + 즉시 듣기
- 태블릿 친화적 그리드
- undo 지원
- 예시 삽입
- 복사/변형 자동화

### 수업 운영

- 로그인 없이 접근 가능
- QR 진입
- 로컬 저장
- 인쇄
- 발표곡 지정

## 14. 가장 큰 한계

1. 음악이론 설명 일부가 지나치게 단순화됨
2. 계이름과 음이름이 혼동될 여지
3. “시작 음”을 조의 기준처럼 설명하는 문장
4. 자연단음계와 V화음의 올림7음 관계 설명 부족
5. 장조=밝음, 단조=어두움의 고정관념 가능성
6. 리듬 표현력이 낮음
7. 실제 오선보와 입력 그리드가 직접 연결되지 않음
8. 로컬 저장 중심이라 교사 제출/수집 기능이 약함
9. 화음 밖 음에 대한 판정은 더 음악적으로 정교해질 필요가 있음

## 15. 자체 구현 시 가장 우선해서 가져올 것

### 반드시 가져올 패턴

- 청음 후 선택
- 단계적 기능 공개
- 4마디 제한
- 씨앗 → 반복 → 변화 → 종지 구조
- 한 번 누르면 수행되는 변형 명령
- 한 마디/가락/화음/전체 분리 재생
- 여러 작품 슬롯
- 발표작 선택
- 즉시 피드백

### 그대로 복제하지 않을 것

- 장조/단조를 감정 단어만으로 고정
- “도에서 시작하면 장조” 같은 정의
- 실제 오선보 없는 최종 결과
- 리듬과 음높이를 하나의 단순 그리드에 무리하게 모두 포함

## 16. 자체 도구로 확장한다면

가장 적합한 구조는 세 표현을 연결하는 것이다.

### 1. 입력

초등학생에게 쉬운 pitch-time grid

### 2. 이해

각 음을 선택하면:

- 계이름
- 음이름
- 현재 화음과의 관계
- 박 위치

를 보여 줌

### 3. 결과

동일한 음악을 **정확한 오선보**로 실시간 변환

즉:

```text
그리드 입력
   ↓
음악 데이터 모델
   ↓
 ┌───────────────┐
 │ 즉시 재생     │
 │ 이론 피드백   │
 │ 오선보 렌더링 │
 └───────────────┘
```

이 구조가 초등학생의 낮은 진입 장벽과 실제 음악 기보 학습을 동시에 만족시키기 가장 좋다.

## 17. 분석 신뢰도

| 영역 | 신뢰도 | 근거 |
|---|---:|---|
| 화면 구성 | 높음 | 실제 배포 페이지 확인 |
